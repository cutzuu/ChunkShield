# FAQ

### I run a larger server, how can I reduce the workload with this?
- Enable the 50% Chance toggles in the configs. This will cut all event checks in half.
- You can also toggle off certain features and enable them when needed.
- If you're still facing issues, increase your **MinimumEntityRequirement** in the config.
- ``` MinimumEntityRequirement: 10    # Recommend 5 - 25. ```
- If you need assistance, check my github profile for all links.

### Will this lag my server?
- No. All checks and scans are performed in singular executions so no mass chunk scanning.
- It takes actions to trigger checks/scans and there is a dice roll to run it once the trigger is primed.
- If it is causing issues, increase your **MinimumEntityRequirement** in the config.
- ``` MinimumEntityRequirement: 10    # Recommend 5 - 25. ```

### Why should people even bother adding this?
- ChunkShield prevents common methods to lag/crash servers. Paper and Spigot do not support preventing this very well.
- Mitigation is left solely up to the server owner as Jar Forks and Mojang have no default measures in place.
- ChunkShield prevents spam of many entities/boats/minecarts/doors and any block of your such as Enchantment Table Chunk Lagging.

### I don't want XYZ feature.
- All features can be toggled however you choose.
- If you need assistance, check my github profile for all links.
